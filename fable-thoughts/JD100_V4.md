# JD100 sentinel v4

Experimental demo runner for the repriced JD100 digit grid. V3 remains unchanged.
V4 does not claim that the historical edge has reopened or that its model is profitable.

## Run

Install `websocket-client`. From the repository root:

```sh
python3 fable-thoughts/tools/adaptive_sentinel_v4.py --minutes 10
python3 fable-thoughts/tools/adaptive_sentinel_v4.py --check-latency
python3 fable-thoughts/tools/adaptive_sentinel_v4.py --trade --stake 1 --minutes 60 --max-trades 100 --max-loss 10
python3 fable-thoughts/tools/adaptive_sentinel_v4.py --continuous --trade --stake 1 --minutes 60 --max-trades 1000000 --max-loss 200 --max-pending 3
```

From `fable-thoughts/tools`, omit the directory prefix. For authenticated modes set
`DERIV_TOKEN` and `DERIV_APP_ID` securely in the environment. Tokens are never command-line
arguments or source constants in v4. There is no real-account override. Watch and latency
diagnostic modes make no purchases. Keep each session's automatically named JSONL file;
custom `--log` paths must not already exist. Restarting resets session risk limits.

## Continuous mode

Add `--continuous` to process a live tick subscription while a separate authenticated
connection polls settlements. The next eligible tick can produce a purchase before an
earlier contract's settlement response arrives. Buys still wait for their acknowledgments,
are never retried, and are limited to one per observed tick epoch. Buffered ticks are
drained to the newest epoch; old signals are not replayed after a slow request.

`--max-pending` defaults to 3 and accepts 1–10. Every pending stake, plus any buy whose
outcome is unknown, remains reserved against the session loss budget. Reaching the pending
cap skips entries until a settlement frees capacity; it does not reset the budget or
end the session. Overlapping positions can lose together and are not independent samples.
Without `--continuous`, the original one-contract-at-a-time runner remains unchanged.

The streamed mode checks five authenticated pings at startup, then refreshes that rolling
five-ping window with one ping every six seconds instead of blocking on a five-ping burst.
The maximum must remain at most 400 ms. It also checks every buy's actual RTT and terms immediately.
Settlement and minute-by-minute quote reads run in one worker, with bounded read-only
recovery restricted to the same demo account. Quotes older than 75 seconds cannot authorize
entries. The tick stream and buy connection are owned by the main thread; only it updates
the risk ledger and writes logs. No socket has concurrent readers.

On a guard failure, duration/count limit, or interruption, no further purchases are sent.
Known contracts are reconciled for up to another 20 seconds, plus any already-running
bounded read. An expired 20-second settlement deadline stops entries before this drain.
Failed reads retain the affected IDs in `pending_contracts`; ambiguous buys set
`unknown_buy_outcome` and retain their stake in `reserved_stake`. Inspect the demo portfolio
before restarting if either remains. Feed/buyer failures stop entries rather than retrying
purchases. Because reconciliation is asynchronous, a late settlement can be discovered
after other orders have already been acknowledged, up to the pending cap.

This changes throughput, not eligibility. At an authenticated multiplier of 1.54 and the
default 1% model gate, spot must be approximately **145.126 or lower**, with the required
current digit. Spots around 146–148 therefore still produce zero trades. Public watch
quotes can differ from authenticated quotes; trading uses authenticated actual-stake quotes.

## Decision rule and payout adaptation

Only UNDER5 on current digit 2 and OVER4 on digit 7 are eligible. The wrapped-normal
probability uses the latest v3 affine fit: sigma = 0.446 + 0.0153254 * spot. V4 replaces
the fixed sigma gate and fitted trailing-table optimization with this explicit model.
It does not fit a new model while trading and does not discard jumps from a training table.

Each side is quoted at the actual stake before the loop and every minute. The decision
multiplier is the LOWER of that quote and 1.56, the conservative reference verified on
$1 demo fills on September 10, 2026. It never assumes a proposal increase is executable.
A lower quote tightens the gate automatically. A fill below the decision assumption is
settled and logged, then trading halts. The first purchase after an unannounced payout cut
cannot be protected by an after-fill check. V4 makes no unconditional startup probe buys.

At reference 1.56 and default `--ev-gate 0.01`, the modeled spot gate is approximately
148.53. A 2% gate (`--ev-gate 0.02`) is approximately 145.92. Higher stakes still use the
1.56 reference cap even if the quote is 1.563. These thresholds extrapolate below the
155.94 minimum of the latest calibration-check sample. They are not empirically verified
reopening levels, confidence bounds, or commands to deploy real money. At spot around
167–169, v4 should simply print status and not trade.

## Execution and risk

The original serial mode uses flat stakes $1–$10 only; no Kelly, martingale, optimizer or parallel positions. Every buy
uses a single non-retrying request, a maximum price equal to stake, and must settle before
another purchase. An uncertain buy or settlement ends the session with its pending state
in the summary. Inspect the demo portfolio before restarting. Ctrl+C records a summary;
interrupting a buy may leave its outcome unknown, and stopping Python does not cancel it.

Authenticated worst-of-five ping RTT must be <=400 ms, repeated every 30 seconds. Tick age
must be <=350 ms and age + measured RTT +250 ms must fit inside one second. The machine
clock must be synchronized. Ping is not proof of order latency. Every fill checks actual
stake, contracted payout, buy RTT <=400 ms, and exit epoch exactly decision epoch +1.
A slow or late trade is allowed to settle, then halts further purchases.

Maximum trade count and duration are bounded. Before buying, the remaining realized-loss
budget must cover another full stake. A pending contract is given up to 20 seconds of
settlement polling beyond the session loop. API calls have their own five-second socket
timeout. Connection/protocol errors stop rather than retry purchases. Public-history
unavailability skips decisions and backs off. Missing or invalid proposal data halts.

Logs separate model assumptions, actual payout, realized profit, lag, decision age and
pending state. Errors log exception types rather than credential-bearing request details.
The serial runner does not reconnect and resume a trading session automatically.

## Validation

```sh
python3 -m unittest discover -s fable-thoughts/tools -p test_adaptive_sentinel_v4.py -v
python3 -m unittest discover -s fable-thoughts/tools -p test_jd100_continuous.py -v
python3 -m unittest discover -s fable-thoughts/tools -p 'test_crash*accu_audit.py' -v
```

Tests exercise threshold calculations, digit selection, stale/invalid ticks, payout
validation, quote inflation, demo-only protection, non-trading diagnostics, risk budgets,
late settlement, adverse fills, ambiguous requests and interruption. Fake executions
validate safety behavior, not profitability. A live watch smoke test is read-only; no
strategy trades should be forced above the gate just to exercise the buy path.
